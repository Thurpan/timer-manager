# Timer Manager v0.2.0

This Windows x64 prerelease adds linked duration/finish editing and clearer timer controls, states and feedback.

## Download and upgrade

Download `TimerManager-win-x64.zip`, extract the complete folder and open `TimerManager.exe`. The ZIP includes the required runtimes, MIT licence and dependency notices. No .NET installation is required. The build is unsigned; a SHA-256 checksum is attached.

Exit the previous version through its tray menu or Settings before opening this version. Existing timers and settings remain in `%LOCALAPPDATA%\TimerManager`, using the compatible version 1 JSON format. If Start with Windows is enabled, disable it before moving the app, then enable it from the new location.

## Changes since v0.1.0

- Create timers by duration or a local finish time. The chosen input is editable; the calculated value stays visible as labelled text.
- Edit duration or finish time while running. Edits preserve counted time; paused timers stay paused and show an estimated finish if resumed now.
- Use compact rows with one actions menu for pause/resume, restart, edit, delete and applicable dismissal.
- See finish information on running rows and remaining/total duration on paused rows. Lime marks unacknowledged completions; paused and dismissed countdowns are muted.
- Distinguish selected controls, keyboard focus and text selection throughout the dark theme. Menus highlight their source timer and separate Delete.
- See counted/remaining snapshots in the editor and validation beside the affected fields. Invalid submissions focus the first error.
- Confirm deletion or restart in a named-timer dialog that defaults to Cancel. Dialogs fit their content and scroll within the available work area.
- See visible/total counts when filtering and use Clear to reset filters. Long tag lists wrap and scroll; the empty dashboard hides sorting.
- Find grouped installation details and Open folder in Settings, with a separate full Exit action.

## Validation and remaining checks

The Release build passes with zero warnings or errors. All 45 core tests and 66 isolated WPF UI checks pass. Fourteen rendered views were inspected, including narrow layouts, editor validation, menus and Settings. The portable archive and checksum were checked.

The WPF runner uses production views and in-memory timer data. It does not start tray, notification or startup-registration services. Remaining manual checks include complete keyboard-only operation and physical Enter/Esc, screen-reader announcements, 150%/200% display scaling, hover/pressed presentation and opening Explorer through Settings.

Visible notification delivery, audible sound, notification-click activation, actual sleep/hibernation/restart/sign-in transitions and a separate Windows PC also remain unverified. Existing API and simulated-clock checks do not establish those outcomes.

See the [validation record and manual acceptance procedure](https://github.com/Thurpan/timer-manager/blob/v0.2.0/docs/validation.md) for details.
